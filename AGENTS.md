# Постановка задачи

Разработать Telegram-бота на Kotlin для ежемесячного расчёта израсходованной электроэнергии по двухтарифному счётчику Т1 и Т2.

## Обязательные функции

- Проект собирается Gradle.
- За каждым пользователем Telegram хранится собственный номер участка. Данные одного пользователя не должны быть доступны или смешиваться с данными другого.
- При первом запуске бот последовательно запрашивает номер участка, тариф Т1 и тариф Т2.
- Меню должно быть кнопочным.
- При внесении показаний Т1 и Т2 бот берёт последние сохранённые тарифы, рассчитывает расход относительно предыдущего показания и сохраняет снимок тарифов вместе с показанием.
- Можно отредактировать только последнее показание, включая каждое показание Т1/Т2 и тариф Т1/Т2. Изменение тарифа последнего показания должно использоваться для следующих показаний.
- Все данные хранятся в собственной SQLite-базе. Ключ изоляции — Telegram user ID.
- В меню нужны действия для копирования сообщения для банка и сообщения для председателя.
- В меню нужны действия для экспорта и импорта личной истории в Excel. Экспорт формируется по `шаблон.xlsx` в корне проекта. Импорт принимает только этот формат, проверяет заголовки, отсутствие пропусков, порядок дат и строгое увеличение Т1/Т2; после успешной проверки транзакционно заменяет только историю текущего пользователя, сообщает число удалённых и загруженных записей, а также старую и новую общую сумму оплаты с разницей. Суммы должны копироваться кнопкой Telegram.
- Экран главного меню показывает номер участка, актуальные тарифы, последнее показание, число личных показаний и общее количество пользователей бота.
- Тексты сообщений берутся из книги `БЮДЖЕТ СНТ СОКОЛЬНИКИ.xlsx`, лист `Т1 и Т2`:
  - `O4` (столбец «сообщение_для_банка») — компактное сообщение для банка;
  - `N4` (столбец «коммент_в_группу») — развёрнутое сообщение для председателя/группы.
- Соблюдать SOLID: классы отвечают за отдельные части работы, зависимости не смешивают транспорт, расчёт и БД. Не создавать формальные интерфейсы без нескольких осмысленных реализаций.

## Правила разработки

- Каждый новый файл добавлять в Git сразу после создания: выполнить `git add <путь-к-файлу>` до следующих правок.
- Денежные тарифы и показания хранить как целые значения в сотых долях, не как `Double`.
- Сумму к оплате округлять до целого рубля по `HALF_UP`, как в исходной Excel-формуле.
- Токен бота не хранить в репозитории: читать из `BOT_TOKEN`.
- Путь к базе задаётся `ELECTRICITY_DB`; по умолчанию — `data/electricity.db`.
- Перед изменением данных проверять, что новое показание не меньше предыдущего для соответствующего тарифа.
- Для каждого пользователя может существовать только одно показание за календарную дату. Это правило должно обеспечиваться проверкой в приложении и уникальным ограничением SQLite по `(telegram_user_id, reading_date)`.
