# Бот учёта электроэнергии Т1/Т2

Telegram-бот на Kotlin для ежемесячного учёта электроэнергии двухтарифного счётчика в СНТ. Пользователь вводит номер участка, тарифы Т1/Т2 и показания. Бот рассчитывает расход относительно предыдущего показания, сумму оплаты, хранит снимок тарифа у каждого показания и формирует тексты для банка и председателя.

## Возможности

- отдельные профиль, тарифы, показания и состояние диалога для каждого Telegram user ID;
- не более одного показания на пользователя за календарные сутки;
- первичная настройка участка и тарифов;
- кнопочное меню для добавления и просмотра показаний, изменения участка и тарифов;
- редактирование последнего показания Т1, Т2, тарифа Т1 или Т2;
- выгрузка личной истории в Excel по шаблону `шаблон.xlsx`;
- безопасный импорт истории из этого Excel-файла: проверяются колонки, отсутствие пропусков, хронология дат и строгое возрастание Т1/Т2; после проверки прежняя история пользователя заменяется одной транзакцией, а бот показывает лог с числом удалённых и загруженных строк;
- сводка в главном меню: участок, действующие тарифы, последнее показание, число личных записей и общее число пользователей;
- кнопки Telegram `copy_text`, которые действительно копируют подготовленный текст в буфер обмена;
- автоматическая проверка официальных тарифов Мосэнергосбыта через отдельный сервис в московском регионе: при обновлении бот уведомляет пользователей и предлагает применить Т1/Т2 кнопкой;
- SQLite без внешнего сервера;
- денежные вычисления без `Double`, с округлением оплаты до рубля по правилам Excel.

Форматы сообщений повторяют формулы из `БЮДЖЕТ СНТ СОКОЛЬНИКИ.xlsx`, лист `Т1 и Т2`: ячейка `O4` для банка и `N4` для председателя/группы. Номер участка подставляется из профиля пользователя.

## Официальные тарифы

Бот получает сохранённые данные из отдельного сервиса тарифов. Этот сервис размещается в московском регионе, запрашивает структурированный ответ официального [тарифного калькулятора Мосэнергосбыта](https://www.mosenergosbyt.ru/individuals/tariffs-n-payments/calc/) при запуске и затем раз в сутки в 03:00 по московскому времени. Используются параметры: Московская область, сельский тариф, электроплита, двухзонный счётчик, первый диапазон потребления.

Когда сайт впервые вернул тарифы или изменил Т1/Т2, бот рассылает уведомление всем настроенным пользователям. При расхождении с вручную установленными тарифами приходит отдельное предупреждение. Рекомендованные тарифы не применяются сами: кнопка «Применить Т1 … · Т2 …» меняет только активные тарифы для будущих показаний, не переписывая историю.

### Связка Miami и Москвы

Telegram-бот остаётся в регионе Miami, где стабилен его доступ к Telegram. Московский сборщик выделен в Gradle-модуль [`tariff-provider`](tariff-provider): он не требует `BOT_TOKEN` и отвечает только на `GET /v1/tariffs`. Доступ защищён заголовком `Authorization: Bearer …` с общим секретом.

1. В Amvera создайте второе приложение в регионе **Москва_0**, подключите тот же репозиторий и используйте конфигурацию [`tariff-provider/amvera.yml`](tariff-provider/amvera.yml):
   - `PORT=8080`;
   - `TARIFF_SERVICE_TOKEN` — новый длинный случайный секрет;
   - `TARIFF_SERVICE_STATE=/data/tariff-service.properties`.
2. В его настройках добавьте бесплатное доменное имя с типом подключения HTTPS. Итоговый URL должен оканчиваться на `/v1/tariffs`.
3. В приложении бота в Miami добавьте те же секрет `TARIFF_SERVICE_TOKEN` и переменную `TARIFF_SERVICE_URL`, например `https://tariff-provider.mister-happyend.amvera.io/v1/tariffs`.
4. Перезапустите оба приложения. Московский сервис сохранит последнюю успешную пару тарифов в постоянном хранилище, а бот будет читать только её. Если связь между приложениями временно пропадёт, бот сохранит уже известные тарифы в своей SQLite-базе.

Не передавайте `TARIFF_SERVICE_TOKEN` в URL, сообщениях или репозитории. У Telegram-бота обе переменные `TARIFF_SERVICE_URL` и `TARIFF_SERVICE_TOKEN` обязательны: прямого запроса к Мосэнергосбыту из Miami в нём больше нет.

## История Excel

Кнопка «Скачать историю Excel» отправляет файл, созданный на основе `шаблон.xlsx` из корня проекта. В нём один лист `ПОКАЗАНИЯ СЧЕТЧИКОВ` и пять колонок: дата, показания Т1, показания Т2, тариф Т1, тариф Т2. Даты должны быть настоящими датами Excel, а не текстом.

Кнопка «Загрузить данные» сначала выдаёт предупреждение и ждёт файл `.xlsx`. До удаления данных бот валидирует весь файл: проверяет структуру, полностью заполненные строки без разрывов, возрастающие даты и строго растущие показания обоих счётчиков. При ошибке существующая история остаётся без изменений. При успехе бот заменяет только историю отправившего файл пользователя, берёт действующие тарифы из последней строки и показывает старую общую сумму оплаты, новую сумму и разницу. Эти три числа можно скопировать одной кнопкой Telegram.

## Запуск

Нужны JDK 25 и токен, полученный у [@BotFather](https://t.me/BotFather).

```powershell
$env:BOT_TOKEN = "123456:replace-with-your-token"
./gradlew.bat run
```

По умолчанию база создаётся в `data/electricity.db`. Чтобы разместить её в другом месте, задайте переменную окружения `ELECTRICITY_DB`:

```powershell
$env:ELECTRICITY_DB = "C:\data\electricity.db"
./gradlew.bat run
```

## Проверка

```powershell
./gradlew.bat test
./gradlew.bat build
```

Два исполняемых JAR-файла собираются одной командой:

```powershell
./gradlew.bat buildAllJars
# build/libs/tg-bot-count-electric-1.0.0.jar
# tariff-provider/build/libs/tariff-provider-1.0.0.jar
```

Локальная интеграционная проверка официального калькулятора не входит в обычную сборку и запускается отдельно:

```powershell
./gradlew.bat :tariff-provider:integrationTest
```

## Docker и развёртывание

Контейнер рассчитан на один постоянно работающий экземпляр бота. SQLite находится в Docker volume, поэтому не потеряется при пересоздании контейнера. Не запускайте несколько реплик: SQLite — локальная файловая БД.

### Локальный запуск контейнера

```powershell
Copy-Item .env.example .env
# В .env укажите настоящий BOT_TOKEN
docker compose up -d --build
docker compose logs -f
```

Остановить контейнер без удаления данных:

```powershell
docker compose down
```

### Amvera Cloud

Для бота подходит сервис «Приложение» на тарифе «Начальный». Он использует
`Dockerfile` и конфигурацию [amvera.yml](amvera.yml), поэтому `compose.yaml`
в Amvera не нужен: Docker Compose сервисом не поддерживается.

1. Создайте проект типа «Приложение», выберите регион Miami и тариф «Начальный».
2. Загрузите исходники через Git или интерфейс Amvera. Не добавляйте `.env` и базу данных в репозиторий.
3. В разделе «Переменные» создайте секрет `BOT_TOKEN` с токеном, полученным у BotFather.
4. Добавьте обычную переменную `ELECTRICITY_DB` со значением `/data/electricity.db`.
5. Запустите сборку. Amvera смонтирует постоянное хранилище в `/data`, поэтому SQLite сохранится после пересборок. Для получения официальных тарифов дополнительно настройте московский сервис по инструкции выше.

Бот использует long polling, поэтому домен и входящие порты не требуются. Для
более стабильного доступа к Telegram рекомендуется регион Miami.

#### Как выкатывать новые версии в Amvera

В текущем проекте развёртывание выполняется прямым push в Git-репозиторий Amvera. Обычный push только в GitHub не запускает обновление приложения, поэтому после каждой готовой версии нужно отправить коммит в оба remote.

Перед первой публикацией на новом компьютере добавьте remote один раз:

```powershell
git remote add amvera https://git.mia0.amvera.ru/mister-happyend/electric-bot
```

Amvera попросит HTTPS-токен при первом `git push`; Git Credential Manager может безопасно сохранить его локально. Не добавляйте токен в URL remote, `.env`, исходники или README.

Обычный цикл разработки и публикации:

```powershell
# 1. Проверить проект локально
.\gradlew.bat test

# 2. Сохранить изменения в Git
git add <изменённые-файлы>
git commit -m "feat: краткое описание изменения"

# 3. Сохранить исходники в GitHub и передать ту же версию в Amvera
git push origin master
git push amvera master
```

После второго push Amvera автоматически соберёт `Dockerfile` и перезапустит приложение. В панели Amvera откройте проект и проверьте статус сборки и логи приложения. Успешный статус — «Запущено»; при ошибке сначала смотрите логи сборки, затем логи приложения.

Не удаляйте и не меняйте без необходимости переменную `ELECTRICITY_DB=/data/electricity.db` и `persistenceMount: /data` в [amvera.yml](amvera.yml): в этом постоянном хранилище лежит рабочая SQLite-база с показаниями пользователей. `BOT_TOKEN` остаётся секретом в переменных Amvera и не должен попадать в коммиты.

## Структура

- `domain` — модели, парсинг, расчёт и формирование сообщений;
- `persistence` — схема и SQL-операции SQLite;
- `application` — сценарии внесения и изменения показаний;
- `telegram` — Telegram Bot API, клавиатуры и обработчик диалога.

Токен и база не попадают в Git. Добавьте реальный `data/` в исключения, если инициализируете репозиторий.
