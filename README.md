# Бот учёта электроэнергии Т1/Т2

Telegram-бот на Kotlin для ежемесячного учёта электроэнергии двухтарифного счётчика в СНТ. Пользователь вводит номер участка, тарифы Т1/Т2 и показания. Бот рассчитывает расход относительно предыдущего показания, сумму оплаты, хранит снимок тарифа у каждого показания и формирует тексты для банка и председателя.

## Возможности

- отдельные профиль, тарифы, показания и состояние диалога для каждого Telegram user ID;
- первичная настройка участка и тарифов;
- кнопочное меню для добавления и просмотра показаний, изменения участка и тарифов;
- редактирование последнего показания Т1, Т2, тарифа Т1 или Т2;
- кнопки Telegram `copy_text`, которые действительно копируют подготовленный текст в буфер обмена;
- SQLite без внешнего сервера;
- денежные вычисления без `Double`, с округлением оплаты до рубля по правилам Excel.

Форматы сообщений повторяют формулы из `БЮДЖЕТ СНТ СОКОЛЬНИКИ.xlsx`, лист `Т1 и Т2`: ячейка `O4` для банка и `N4` для председателя/группы. Номер участка подставляется из профиля пользователя.

## Запуск

Нужны JDK 25 и токен, полученный у [@BotFather](https://t.me/BotFather).

```powershell
$env:BOT_TOKEN = "123456:replace-with-your-token"
./gradlew.bat run
```

По умолчанию база создаётся в `data/electricity.db`. Чтобы разместить её в другом месте, задайте переменную окружения `ELECTRICITY_DB`:

```powershell
$env:ELECTRICITY_DB = "C:\data\electricity.db"
./gradlew.bat run
```

## Docker и развёртывание

Контейнер рассчитан на один постоянно работающий экземпляр бота. SQLite находится в Docker volume, поэтому не потеряется при пересоздании контейнера. Не запускайте несколько реплик: SQLite — локальная файловая БД.

### Локальный запуск контейнера

```powershell
Copy-Item .env.example .env
# В .env укажите настоящий BOT_TOKEN
docker compose up -d --build
docker compose logs -f
```

Остановить контейнер без удаления данных:

```powershell
docker compose down
```

### Amvera Cloud

Для бота подходит сервис «Приложение» на тарифе «Начальный». Он использует
`Dockerfile` и конфигурацию [amvera.yml](amvera.yml), поэтому `compose.yaml`
в Amvera не нужен: Docker Compose сервисом не поддерживается.

1. Создайте проект типа «Приложение», выберите регион Miami и тариф «Начальный».
2. Загрузите исходники через Git или интерфейс Amvera. Не добавляйте `.env` и базу данных в репозиторий.
3. В разделе «Переменные» создайте секрет `BOT_TOKEN` с токеном, полученным у BotFather.
4. Добавьте обычную переменную `ELECTRICITY_DB` со значением `/data/electricity.db`.
5. Запустите сборку. Amvera смонтирует постоянное хранилище в `/data`, поэтому SQLite сохранится после пересборок.

Бот использует long polling, поэтому домен и входящие порты не требуются. Для
более стабильного доступа к Telegram рекомендуется регион Miami.

### Первый запуск на Yandex Cloud

Для текущей реализации проще всего использовать небольшую Compute Cloud VM с Ubuntu и постоянным загрузочным диском. Container Registry для первого запуска не нужен.

1. Создайте VM в Yandex Cloud и разрешите SSH. Боту нужен исходящий доступ по HTTPS (порт 443) к `api.telegram.org`; входящие порты для long polling не нужны.
2. Подключитесь по SSH, установите Docker Engine и Docker Compose Plugin.
3. Клонируйте этот репозиторий, создайте `.env` из `.env.example` и впишите токен.
4. Выполните `docker compose up -d --build`.
5. Проверьте `docker compose logs -f`. Данные будут храниться в Docker volume на диске VM.

Для автоматических развёртываний образ можно собрать и отправить в Yandex Container Registry, а VM настроить на его скачивание. Это не обязательно, пока обновления редки.

## Структура

- `domain` — модели, парсинг, расчёт и формирование сообщений;
- `persistence` — схема и SQL-операции SQLite;
- `application` — сценарии внесения и изменения показаний;
- `telegram` — Telegram Bot API, клавиатуры и обработчик диалога.

Токен и база не попадают в Git. Добавьте реальный `data/` в исключения, если инициализируете репозиторий.
